# TGuard

Утилита для блокировки сканеров портов через iptables и ipset с поддержкой логирования и агрегации статистики.

Простой менеджер с интерактивным меню, управлением IP вручную и автозагрузкой правил.

## О проекте

### Зачем это нужно?

**TGuard** — это инструмент сетевой безопасности, который защищает ваш сервер от автоматизированного сканирования портов и несанкционированных попыток подключения.

**Основные проблемы, которые решает:**

1. **Массовое сканирование портов** — сканеры постоянно проверяют открытые порты на серверах в интернете, создавая нагрузку и потенциальные риски

2. **Нагрузка на сервисы** — каждая попытка подключения потребляет ресурсы сервера (CPU, память, трафик). При массовом сканировании это замедляет работу легитимных сервисов

3. **Риски безопасности** — сканирование часто является первым этапом атаки. Злоумышленники ищут уязвимые сервисы и открытые порты

4. **Засорение логов** — попытки подключения от сканеров заполняют системные логи, затрудняя анализ реальных проблем

5. **Неэффективное использование ресурсов** — ваши сервисы (веб-сервер, SSH, база данных) тратят время на обработку запросов от сканеров вместо реальных пользователей

**TGuard блокирует весь трафик с известных IP-адресов сканеров на уровне сетевого фильтра (iptables), до того как пакеты достигнут ваших сервисов.**

### Способы использования

#### 1. Базовая защита сервера

Защитите ваш VPS/сервер от массовых сканеров:

```bash
sudo tguard install
```

**Результат:** устанавливается бинарник `tguard`, подтягиваются списки подсетей, настраиваются правила iptables/ipset. Весь трафик с известных сканеров отбрасывается на уровне firewall.

#### 2. Управление через интерактивное меню

```bash
sudo tguard
```

**Результат:** открывается меню с текущей статистикой (подсети, атаки), пунктами для просмотра логов, управления IP, обновления списков.

#### 3. Обновление списков

```bash
sudo tguard update
```

**Результат:** перекачиваются актуальные списки из репозитория [Adieuwhine/TGuard](https://github.com/Adieuwhine/TGuard) и применяются к текущим правилам.

#### 4. Собственные списки блокировки

Если нужно добавить свои подсети — используйте встроенный пункт меню **🧪 Управление IP**, либо редактируйте вручную:

```bash
# Список ручных банов
cat /opt/tguard-manual.list

# Формат: по одному IP на строку
192.168.1.10
10.0.0.5
```

### Правовой статус и легальность

**⚖️ ВАЖНОЕ ЮРИДИЧЕСКОЕ РАЗЪЯСНЕНИЕ**

#### Что это такое юридически?

**TGuard является легальным инструментом сетевой безопасности класса "firewall" (межсетевой экран).**

#### Правовая квалификация

1. **Это обычный firewall** — TGuard использует стандартные механизмы Linux (iptables/ipset), штатные компоненты ОС для управления сетевым трафиком

2. **Законное право на защиту** — владелец сервера/инфраструктуры имеет полное законное право контролировать входящие соединения и блокировать нежелательный трафик

3. **Аналог антивируса** — так же как антивирус блокирует вредоносные программы, TGuard блокирует подозрительный сетевой трафик

#### Что делает утилита с точки зрения закона?

- ✅ **Блокирует входящие подключения** к вашему серверу с определённых IP-адресов
- ✅ **Не осуществляет атаки** на другие системы
- ✅ **Не перехватывает чужой трафик**
- ✅ **Не нарушает работу других систем**
- ✅ **Защищает только вашу инфраструктуру**

Это аналогично тому, как вы закрываете дверь в свой дом или устанавливаете сигнализацию.

#### Правовые основания (Российская Федерация)

**Статья 16 Федерального закона от 27.07.2006 N 149-ФЗ "Об информации":**

> Владелец информационной системы вправе устанавливать ограничения доступа к информации

**Статья 209 ГК РФ (право собственности):**

> Собственник вправе по своему усмотрению совершать в отношении принадлежащего ему имущества любые действия

**Федеральный закон от 27.07.2006 N 152-ФЗ "О персональных данных":**

> Оператор обязан принимать необходимые меры по защите персональных данных

#### Может ли быть привлечение к ответственности?

**НЕТ**, если вы:

- Используете утилиту для защиты **собственной инфраструктуры**
- Блокируете только **входящий трафик на свой сервер**
- Не используете для атак или нарушения работы других систем

**TGuard НЕ является:**

- ❌ Средством взлома
- ❌ Инструментом DDoS-атак
- ❌ ПО для незаконного доступа к информации
- ❌ Средством обхода защиты

**Вы имеете право решать, кто может подключаться к вашему серверу.**

#### Для государственных органов

Если представители правоохранительных органов интересуются этой утилитой:

**TGuard — это стандартный межсетевой экран (firewall), который:**

1. Использует только легальные системные компоненты Linux (iptables, ipset)
2. Блокирует входящие соединения к защищаемому серверу
3. Не осуществляет никаких активных действий в сторону других систем
4. Является инструментом защиты информации, аналогичным коммерческим решениям (Cisco ASA, pfSense, и т.д.)
5. Реализует требования по защите информации согласно 152-ФЗ и другим нормативным актам

**Использование данной утилиты является законным осуществлением права на защиту собственной информационной инфраструктуры.**

#### Рекомендации

- ✅ Используйте для защиты собственных серверов
- ✅ Документируйте настройки безопасности
- ✅ Храните логи в соответствии с требованиями законодательства
- ❌ Не используйте для блокировки доступа к чужим ресурсам
- ❌ Не используйте в составе инфраструктуры для незаконной деятельности

## Быстрый старт

Установка и запуск за 30 секунд:

```bash
curl -fsSL https://raw.githubusercontent.com/Adieuwhine/TGuard/main/install-tguard.sh | sudo bash
```

После установки команда `tguard` доступна из любого места.

## Установка

### Автоматическая установка

Скачайте и запустите установочный скрипт:

```bash
curl -fsSL https://raw.githubusercontent.com/Adieuwhine/TGuard/main/install-tguard.sh | sudo bash
```

или

```bash
wget -qO- https://raw.githubusercontent.com/Adieuwhine/TGuard/main/install-tguard.sh | sudo bash
```

Скрипт автоматически:

- Ищет и удаляет остатки предыдущих установок (в `/opt`, `/usr/local/bin`, `/usr/bin`, `/bin`, `/sbin` и др.)
- Создаёт менеджер `/opt/tguard-manager.sh`
- Создаёт симлинк `/usr/local/bin/tguard`
- Определяет архитектуру системы (amd64, 386, arm, arm64)
- Скачивает последний релиз `tguard` из `Adieuwhine/TGuard`
- Устанавливает бинарник в `/opt/tguard` + симлинк в `/usr/local/bin/tguard`
- Ставит необходимые пакеты (curl, wget, rsyslog, ipset, ufw, …)
- Подтягивает списки подсетей из `Adieuwhine/TGuard/lists/`
- Настраивает правила iptables/ipset

### Ручная установка

1. Клонируйте репозиторий:

```bash
git clone https://github.com/Adieuwhine/TGuard.git
cd TGuard
sudo bash install-tguard.sh
```

2. Либо скачайте бинарник `tguard` из [последнего релиза](https://github.com/Adieuwhine/TGuard/releases/latest) вручную:

```bash
sudo mv tguard-linux-* /opt/tguard
sudo chmod +x /opt/tguard
sudo ln -sf /opt/tguard /usr/local/bin/tguard
```

- 🧹 **Чистое удаление** — удаление всех следов из системы одной командой
- 🧽 **Автоочистка** при переустановке — старые файлы из любых папок удаляются автоматически

## Использование

### Меню

Запустите `tguard` без аргументов — откроется интерактивное меню:

```
  🛡️   TGUARD  · v0.1
  ──────────────────────────────────────────────
  📊  Подсетей          2931
  🔥  Атак отбито         12
  ──────────────────────────────────────────────

  1   📈  Топ атак            CSV
  2   🕵   Логи IPv4           live
  3   🕵   Логи IPv6           live
  4   🧪  Управление IP        ban / unban
  5   🔄  Обновить списки     update
  6   🛠️   Переустановить      reinstall
  7   🗑️   Удалить             uninstall

  0   ❌  Выход

  👉  Ваш выбор:
```

### Команды

```bash
tguard                # Открыть интерактивное меню (по умолчанию)
tguard install        # Установить TGuard
tguard update         # Обновить списки блокировок
tguard uninstall      # Удалить TGuard
tguard --version      # Показать версию
tguard --help         # Показать справку
```

### Списки блокировки

Списки подсетей сканеров лежат в репозитории:

**[Adieuwhine/TGuard/lists](https://github.com/Adieuwhine/TGuard/tree/main/lists)**

Доступные списки:

- `lists/antiscan.list` — публичные сканеры
- `lists/gov.list` — подсети сканеров государственных организаций
- `lists/misc.list` — дополнительные подсети

TGuard по умолчанию использует все три списка при `install` и `update`.

## Управление IP

В меню выберите **🧪 Управление IP**:

- **Забанить IP** — добавляет адрес в ipset `SCANNERS-BLOCK-V4`, трафик с него блокируется немедленно
- **Разбанить IP** — показывает список вручную забаненных адресов, можно выбрать номер или ввести IP

Все ручные баны сохраняются в `/opt/tguard-manual.list` и переживают перезагрузку.

## Удаление (uninstall)

```bash
sudo tguard uninstall
```

Команда пошагово удаляет изменения, внесённые TGuard:

- удаляет правила и цепочку `SCANNERS-BLOCK` из `iptables/ip6tables`
- удаляет managed-блоки из `/etc/ufw/before.rules` и `/etc/ufw/before6.rules`
- удаляет наборы `ipset` (`SCANNERS-BLOCK-V4`, `SCANNERS-BLOCK-V6`)
- останавливает и отключает сервисы `antiscan-*`, удаляет созданные unit-файлы
- удаляет конфиги rsyslog/logrotate и скрипт агрегации
- удаляет менеджер `/opt/tguard-manager.sh`, симлинк `/usr/local/bin/tguard`, список ручных банов
- удаляет бинарник `/opt/tguard` и симлинк `/usr/local/bin/tguard`

Что **не** делает uninstall:

- не удаляет системные пакеты (`iptables`, `ipset`, `netfilter-persistent`)
- не удаляет логи в `/var/log` по умолчанию

## Логирование

### Конфигурация

При включении логирования создаются:

1. **`/etc/rsyslog.d/10-iptables-scanners.conf`** — конфигурация rsyslog
2. **`/etc/logrotate.d/iptables-scanners`** — ротация логов
3. **`/usr/local/bin/antiscan-aggregate-logs.sh`** — скрипт агрегации
4. **`/etc/systemd/system/antiscan-aggregate.service`** — systemd service
5. **`/etc/systemd/system/antiscan-aggregate.timer`** — systemd timer

### Файлы логов

- **`/var/log/iptables-scanners-ipv4.log`** — сырые логи IPv4
- **`/var/log/iptables-scanners-ipv6.log`** — сырые логи IPv6
- **`/var/log/iptables-scanners-aggregate.csv`** — агрегированная статистика в CSV

### Формат агрегированного CSV

```csv
IP_TYPE|IP_ADDRESS|ASN|NETNAME|COUNT|LAST_SEEN
v4|85.142.100.138|AS49505|JSCCYBEROK-NET|237|2026-01-25T17:08:01.123456+03:00
v6|2001:db8::1|AS12345|EXAMPLE-NET|12|2026-01-25T17:08:05.987654+03:00
```

**Поля:**

- `IP_TYPE` — тип IP (v4/v6)
- `IP_ADDRESS` — IP адрес сканера
- `ASN` — номер автономной системы (из whois)
- `NETNAME` — имя сети (из whois)
- `COUNT` — количество попыток подключения
- `LAST_SEEN` — время последней попытки

**Особенности:**

- Whois lookup с кэшированием (не повторяется для одного IP)
- Таймаут lookup: 3 секунды
- CSV отсортирован по COUNT (самые активные сверху)

### Просмотр логов

```bash
# Последние агрегированные данные
tail -f /var/log/iptables-scanners-aggregate.csv

# Статус systemd timer
systemctl status antiscan-aggregate.timer

# Логи агрегатора
journalctl -u antiscan-aggregate.service -f
```

Либо через меню: **📈 Топ атак**, **🕵 Логи IPv4**, **🕵 Логи IPv6**.

## Что создается в системе

### iptables

- **Цепочка**: `SCANNERS-BLOCK`
- **Правила**:
  - IPv4: `INPUT -j SCANNERS-BLOCK`
  - IPv6: `INPUT -j SCANNERS-BLOCK`
  - `SCANNERS-BLOCK -m set --match-set SCANNERS-BLOCK-V4 src -j DROP` (IPv4)
  - `SCANNERS-BLOCK -m set --match-set SCANNERS-BLOCK-V6 src -j DROP` (IPv6)

С логированием добавляются дополнительные правила с rate-limit.

### ipset

- **Наборы**:
  - `SCANNERS-BLOCK-V4` — hash:net для IPv4
  - `SCANNERS-BLOCK-V6` — hash:net для IPv6
- **Конфигурация**: `/etc/ipset.conf`

### UFW

Managed-блоки в `/etc/ufw/before.rules` и `/etc/ufw/before6.rules` — ссылки на ipset, обрабатываются раньше пользовательских правил UFW.

### Файлы TGuard

| Файл | Назначение |
|---|---|
| `/opt/tguard-manager.sh` | Менеджер (интерактивное меню, все команды) |
| `/usr/local/bin/tguard` | Симлинк на менеджер |
| `/opt/tguard` | Бинарник tguard |
| `/usr/local/bin/tguard` | Симлинк на бинарник (совпадает с менеджером — управляется через `install`) |
| `/opt/tguard-manual.list` | Список ручных банов |

### Автозагрузка

Правила автоматически сохраняются:

- **Debian/Ubuntu**: `/etc/iptables/rules.v4`, `/etc/iptables/rules.v6`
- **RedHat/CentOS**: через `service iptables save`
